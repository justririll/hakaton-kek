# Культурный пульс

Аналитическая платформа для сети центров прототипирования и творческих
инкубаторов, созданных на базе вузов культуры. Агрегирует ведомственную
отчётность двадцати организаций, находит аудиторные модели работы, оценивает
исполнение плана и выдаёт рекомендации по программированию мероприятий с
оценкой ожидаемого эффекта.

```
DATASET/*.xlsx  →  парсер Форм 1 и 2  →  признаки  →  кластеризация  →  рекомендации
   20 книг          контроль качества     11 призн.    5 моделей         50 действий
```

---

## 1. Что в данных на самом деле

Задача формулировалась как «посещаемость, обратная связь и вовлечённость
аудитории учреждений культуры». Выданный датасет — это **ежеквартальная
отчётность по контрольной точке госпрограммы «Развитие культуры»**: двадцать
книг Excel, Формы 1 и 2, отчётный период девять месяцев 2026 года.

Что из требуемого в данных есть, а чего нет:

| Требование ТЗ | Что реально есть | Как закрыто |
|---|---|---|
| Посещаемость | строки 3.1–3.4 Формы 2: число человек, прошедших обучение по четырём форматам | полностью — это и есть аудитория центра |
| Вовлечённость | строки 3, 3.5, 4.x: резиденты и созданные творческие продукты; строки 1–2: публикации и федеральные площадки | полностью — вовлечённость измеряется конверсией «участник → продукт» |
| Обратная связь | **отсутствует** — ни оценок, ни отзывов, ни NPS | не подменяется выдумкой (см. ниже) |
| Графики динамики | две точки: значение 2025 года и факт девяти месяцев 2026 | план-факт, темп и прогноз года вместо временного ряда |
| Кластеризация аудитории | микроданных участников нет, есть агрегаты по центрам | кластеризуются **аудиторные модели центров** |

### Про обратную связь

Её в датасете нет. Синтетические оценки можно было бы сгенерировать за час, но
дашборд, где половина метрик придумана, не годится для решений — и на защите
первый же вопрос «откуда цифра» это вскрывает. Поэтому вместо выдуманного NPS
сделано следующее:

* все выводы платформы опираются только на наблюдаемые показатели;
* там, где обратная связь была бы уместна, используются её наблюдаемые
  заменители — конверсия в продукты (участник довёл работу до результата) и
  доля резидентов (участник вернулся);
* контур для реальной обратной связи предусмотрен: `POST /api/reload`
  пересобирает модели из исходного каталога, схема показателей расширяется
  одной записью в `app/ingest/schema.py`.

### Про кластеризацию аудитории

Двадцать организаций — это двадцать наблюдений, а не двадцать тысяч
посетителей. Кластеризовать посетителей не на чем: персональных данных в
отчётности нет и быть не должно. Но у каждого центра есть **профиль аудитории**
— распределение обученных по четырём форматам плюс глубина и отдача работы с
ними. Именно этот профиль и кластеризуется: результат отвечает на вопрос «какие
аудиторные модели существуют в сети и кто с кем сопоставим», а это то, ради
чего кластеризация в такой задаче и нужна — чтобы было с кем сравнивать.

## 2. Быстрый старт

```bash
./run.sh          # поднимает бэкенд и фронтенд разом
```

Скрипт сначала устанавливает зависимости (при первом запуске нужен интернет),
затем запускает оба сервера. Открывайте http://127.0.0.1:5173 после сообщения
Vite `Local`; API готов после сообщения `Application startup complete`.
Ошибки установки выводятся в терминал. Порт 5173 должен быть свободен.
`Ctrl+C` останавливает серверы и установку, если она ещё идёт.

или по отдельности:

```bash
# бэкенд (Python 3.11+, uv)
cd backend
uv sync
uv run uvicorn app.main:app --reload --port 8000
# → http://127.0.0.1:8000/docs — интерактивная документация API

# демо-интерфейс ML-части (Node 20+)
cd frontend-ml
npm install
npm run dev
# → http://127.0.0.1:5173
```

Каталог с отчётами задаётся переменной `CULTURE_PULSE_DATA`
(по умолчанию — `DATASET/` в корне репозитория).

Полный конвейер — разбор двадцати книг, признаки, кластеризация, валидация,
рекомендации и поиск аномалий — считается **за 6,7 с** и держится в памяти
процесса.

│   ├── recommender.py    правила, оценка эффекта, приоритизация

│   └── pipeline.py       сборка всего в один объект

├── theme.js              палитра, прошедшая контроль цветовой различимости

В репозитории два интерфейса. `frontend/` — основной Vue 3 + TypeScript фронт
команды, работающий с контрактом `/api/v1/analytics/dashboard`. `frontend-ml/` —
демонстрационный интерфейс ML-части: он ходит в описанный ниже API напрямую и
служит витриной для моделей. Ветка не затрагивает файлы основного фронта.

## 4. Слой данных

### 4.1. Разбор

Двадцать организаций заполняют один шаблон, но расхождения есть в каждой
второй книге: лишний пробел в имени листа (`'ФОРМА 1 '`), `.xls` вместо
`.xlsx`, вставленные строки со ссылками на подтверждающие документы,
переименованная колонка «Фактическое значение…» → «Значение показателя 2026
года», стёртые служебные подписи на титуле.

Поэтому парсер не опирается на координаты ячеек:

1. роль листа определяется по названию (`ФОРМА 1`, `ПРИЛОЖ`, `ФОРМА 2`, `ТИТУЛ`);
2. строка заголовка ищется по вхождению «Наименование», карта колонок строится
   по ключевым словам;
3. показатель опознаётся по номеру строки (`3.1`, `4.2`) — нумерация шаблона
   стабильна во всех книгах, — а название сверяется с эталонными ключевыми
   словами как контрольная проверка;
4. организация и центр читаются из блока под «Предоставляет:» — единственной
   структурно устойчивой опоры на титуле.

**Результат: 20 из 20 книг разобраны, 0 предупреждений, заполненность матрицы
показателей 100 %.**

### 4.2. Контроль качества: что нашли

| Организация | Находка | Решение |
|---|---|---|
| МГАХИ | строка «Объём оказанных услуг» подписана **тыс. рублей**, значение 2 225,01 | приведено к рублям: 2 225 010 ₽ |
| Новосибирская консерватория | та же строка подписана **тыс.рублей**, значение 533 500 | при переводе получилось бы 533,5 млн ₽ — в 475 раз выше медианы сети. Подпись признана ошибочной, значение оставлено в рублях |
| АГИК | сумма подпунктов 4.1–4.5 (131) не сходится с итогом строки 4 (115) | расхождение зафиксировано, используется заявленный итог |
| 23 строки в 5 книгах | пустая ячейка счётного показателя | истолкована как «деятельности не было» → 0, каждая подмена залогирована |

Правило нормализации единиц намеренно двухступенчатое: подпись «тыс. рублей»
применяется, только если после перевода значение остаётся правдоподобным на
фоне выборки (не более чем в 50 раз от медианы организаций, отчитавшихся
рублями). Слепой перевод по подписи исказил бы всю экономику сети на два
порядка из-за одной опечатки.

Полный отчёт — `GET /api/quality` и раздел «Качество данных» в интерфейсе.

## 5. Кластеризация аудиторных моделей

### 5.1. Признаки

Одиннадцать признаков, четыре смысловых блока. Пространство намеренно
экономное: на двадцати наблюдениях каждый лишний признак — это шум.

| Признак | Блок | Смысл |
|---|---|---|
| `clr_modules` | состав | Перевес аудитории в сторону образовательных модулей |
| `clr_masterclasses` | состав | Перевес в сторону мастер-классов |
| `clr_cpd` | состав | Перевес в сторону повышения квалификации |
| `clr_retraining` | состав | Перевес в сторону переподготовки |
| `log_audience` | масштаб | Размер аудитории, log(1+x) |
| `log_supply` | масштаб | Число разработанных форматов, log(1+x) |
| `audience_per_format` | глубина | Участников на один формат, log(1+x) |
| `resident_rate` | глубина | Доля аудитории, ставшей резидентами |
| `product_rate` | отдача | Творческих продуктов на участника |
| `revenue_per_participant` | отдача | Выручка на участника, ₽, log(1+x) |
| `publicity_per_format` | отдача | Публикаций и федеральных выходов на формат |

**Почему CLR, а не просто доли.** Доли четырёх форматов — композиционные
данные: они лежат на симплексе и в сумме всегда дают единицу. Из-за этого они
линейно зависимы, а евклидово расстояние между ними искажает близость (рост
одной доли механически уменьшает остальные). Применяется центрированное
логарифмическое преобразование с мультипликативной заменой нулей —
стандартная практика для составов. Нулей здесь много и они содержательны
(«центр не ведёт переподготовку»), поэтому псевдосчёт берётся малым
(0,5 / число компонент) и остальные компоненты пропорционально ужимаются.

Тяжёлые хвосты (аудитория от 12 до 1479 человек) гасятся `log1p`, затем всё
стандартизуется и проецируется в пространство главных компонент: **5 компонент,
89,5 % дисперсии**.

### 5.2. Выбор числа кластеров

Силуэт и Calinski–Harabasz на малой выборке растут почти монотонно по k — если
выбирать по ним напрямую, ответ всегда упрётся в верхнюю границу диапазона и
породит кластеры из одного объекта. Поэтому выбор ограничен и многокритериален:

* диапазон k ограничен сверху как `n / 4` — иначе сегменты нечем наполнять;
* разбиения с кластером меньше двух объектов отбрасываются (это выброс, а не
  сегмент);
* сводная оценка = 0,30 · силуэт + 0,30 · устойчивость + 0,15 · CH + 0,15 · DB
  (обратно) + 0,10 · баланс размеров, каждая метрика нормирована внутри набора
  кандидатов;
* **правило парсимонии**: среди разбиений, отстающих от лучшего не более чем на
  0,05, берётся наименьшее k.

Устойчивость меряется бутстрэпом: на каждом из 200 раундов берутся две
пересекающиеся подвыборки по 80 %, кластеризуются независимо, согласие
считается через ARI на их пересечении. Так проверяется воспроизводимость
структуры, а не совпадение подвыборки с полным решением.

| k | Силуэт | CH | DB | Устойчивость | Баланс | Сводная | Размеры |
|---:|---:|---:|---:|---:|---:|---:|---|
| 2 | 0,320 | 6,33 | 1,052 | 0,300 | 0,18 | 0,352 | 17 / 3 |
| 3 | 0,243 | 6,52 | 1,241 | 0,420 | 0,27 | 0,231 | 11 / 6 / 3 |
| 4 | 0,288 | 7,49 | 1,052 | 0,527 | 0,22 | 0,592 | 9 / 6 / 3 / 2 |
| **5** | **0,326** | **8,32** | **0,849** | **0,610** | **0,25** | **0,976** | **8 / 5 / 3 / 2 / 2** |

**Выбрано k = 5.**

### 5.3. Найденные модели

| # | Архетип | n | Силуэт | Состав | Чем выделяется |
|---:|---|---:|---:|---|---|
| 0 | **Массовые просветители** | 8 | 0,23 | АГИК, Академия Андрияки, ВГИИ, КГИК, МГАХИ, ОГИК, СПбГИКиТ, ВСГИК | массовый охват, широкая линейка форматов, слабое медийное сопровождение |
| 1 | **Медийные площадки** | 5 | 0,46 | ЕГТИ, КемГИК, МГИК, ПГИК, ЧГИК | заметность в медиа при камерном формате и узкой линейке |
| 2 | **Продуктовые мастерские** | 3 | 0,18 | Нижегородская, Новосибирская консерватории, ГМПИ им. Ипполитова-Иванова | сильное ядро резидентов, высокая отдача в продуктах, штучная работа |
| 3 | **Открытые бесплатные площадки** | 2 | 0,63 | Карандаш, Театриум (ПГХУ) | бесплатная модель, крупные потоки, узкая линейка |
| 4 | **Профессиональные академии** | 2 | 0,29 | Саратовская консерватория, УГИИ | ставка на повышение квалификации и мастер-классы |

Имена архетипов присваиваются автоматически: берутся три признака, по которым
центроид кластера сильнее всего отстоит от центра сети, каждый переводится в
словесный ярлык, и по сильнейшему незанятому ярлыку подбирается архетип из
словаря. Двух кластеров с одинаковым названием быть не может — одинаковые имена
ничего не объясняют.

### 5.4. Валидация

Кластеризация вернёт k групп на любых данных, включая чистый шум, поэтому
результат проверяется тремя независимыми способами.

**Есть ли структура вообще — перестановочный тест.** Метки перемешиваются 2000
раз (размеры кластеров сохраняются), каждый раз считается силуэт:

| | Значение |
|---|---|
| Силуэт реального разбиения | **0,326** |
| Силуэт случайных разбиений | −0,176 ± 0,054 |
| p-значение | **0,0005** |
| Размер эффекта | **9,35 σ** |

**Воспроизводима ли структура — leave-one-out.** Каждый центр по очереди
исключается, сеть кластеризуется заново, результат сверяется с полным решением:

| | Значение |
|---|---|
| Средний ARI по 20 прогонам | **0,982** |
| Минимальный ARI | 0,849 |
| Центров со спорной принадлежностью | **0** |

Заодно считается, как часто каждая пара центров попадает в один кластер. Ниже
всех уверенность у Новосибирской консерватории (0,861) — что согласуется с
пометкой детектора аномалий по её отчёту.

**Согласие алгоритмов.** Одно и то же пространство разбивается тремя методами:

| Пара | ARI |
|---|---|
| KMeans ~ Ward | **1,000** |
| GMM ~ KMeans | 0,757 |
| GMM ~ Ward | 0,757 |

KMeans и Ward дали идентичные разбиения — структура не артефакт конкретного
метода.

**Вердикт модели:** структура значима и устойчива, разбиение пригодно для
решений.

## 6. Рекомендации по программированию

### 6.1. Принцип

Центр сравнивается не со всей сетью, а со своим кластером. Сравнивать камерную
лабораторию с массовым просветителем бессмысленно; внутри кластера разрыв с
эталоном означает **достижимый** резерв — кто-то из соседей по модели его уже
закрыл в сопоставимых условиях.

Эталон считается методом исключения: сам центр не входит в выборку, по которой
для него же считается норма. Иначе лидер кластера всегда сравнивался бы сам с
собой и никогда не получал бы рекомендаций. Если в кластере меньше трёх соседей,
группа расширяется до всей сети — с понижающим коэффициентом доверия.

### 6.2. Правила

| Тип | Когда срабатывает | Эффект считается как |
|---|---|---|
| `fix_format` | формат ведётся, но наполняемость ниже нижнего квартиля группы | (медиана группы − своё) × число мероприятий |
| `expand_format` | формат собирает не ниже медианы, но занимает меньшую долю линейки, чем у соседей | +25 % мероприятий × своя наполняемость |
| `launch_format` | формат не ведётся, а его ведут ≥ 60 % соседей | одна медианная наполняемость группы |
| `raise_conversion` | продуктов на участника меньше медианы группы | (медиана − своё) × своя аудитория |
| `monetize` | выручка на участника ниже медианы группы | (медиана − своё) × своя аудитория |
| `amplify_visibility` | публикаций на мероприятие меньше медианы группы | (медиана − своё) × число мероприятий |
| `plan_risk` | прогноз года не выходит на цель Формы 1 | недостающие мероприятия до цели |

Эффект всегда в натуральных единицах — участники, продукты, рубли, публикации,
мероприятия, — а не в абстрактных баллах.

### 6.3. Доверие и приоритет

**Доверие** к рекомендации собирается из трёх множителей:

```
доверие = размер_группы/(размер_группы+2) · 1/(1+относительный_IQR) · штраф_за_расширение
```

то есть падает и когда соседей мало, и когда они разнородны, и когда группу
пришлось расширять с кластера до сети. Диапазон ограничен [0,15; 0,95].

**Приоритет** — перцентиль сырой оценки по всей сети:

```
сырая_оценка = min(выигрыш / текущий_уровень, 2)/2 · доверие · вес_типа
приоритет    = перцентиль(сырая_оценка) по всем рекомендациям сети
```

Выигрыш нормируется на текущий уровень той же метрики у самого центра: «плюс 20
участников» значит разное для центра с аудиторией 30 и 1479. Вес типа отражает
управляемость действия: донастроить существующий формат (1,00) дешевле, чем
запустить новый (0,55). Абсолютное значение оценки руководителю ничего не
сообщает, а место в очереди резервов — сообщает: приоритет 90 означает верхние
10 % резервов сети.

## 7. Аномалии

Две разные задачи решаются раздельно, потому что и реагировать на них нужно
по-разному.

**Логические противоречия** внутри одного отчёта — почти всегда дефект
заполнения, и он обесценивает любые выводы по центру, пока не разобран.

**Статистические выбросы** — не ошибка: так выглядят и лидер, и провал. Задача
— заметить. Используется модифицированная z-оценка на медиане и MAD (порог 3,5,
критерий Иглвича–Хоаглина): обычная z-оценка здесь не работает, потому что
выброс входит и в среднее, и в стандартное отклонение, маскируя сам себя.

**Многомерные выбросы** ищет Isolation Forest: он видит центр, у которого каждый
показатель по отдельности в норме, но их сочетание в сети не встречается — для
таких автоматические эталоны менее надёжны.

Найдено 17 аномалий: 1 ошибка, 5 предупреждений, 11 наблюдений.

Главная находка:

> **Новосибирская консерватория** — разработано 69 форматов при 21 обученном
> человеке: меньше одного участника на формат. Вероятна ошибка в строках
> 3.1–3.4 Формы 2 либо в приложении к Форме 1.

Именно этот центр получил и самый высокий приоритет рекомендации, и самую низкую
уверенность принадлежности к кластеру — три независимых модуля сошлись на одном
и том же отчёте.

## 8. План и прогноз

Обязательство Формы 1 — прирост числа мероприятий на 10 % к предыдущему году.
Отчёт сдан за девять месяцев нарастающим итогом, поэтому считаются:

* **выполнение** — факт к цели года;
* **прогноз при текущем темпе** — факт × 12/9;
* **требуемый темп остатка года** — сколько мероприятий нужно за оставшийся
  квартал и с какой месячной интенсивностью.

Экстраполяция сознательно линейная. Сезонность вузовского года (спад летом, пик
осенью) достоверно оценить не на чем — в данных один срез, а не ряд. Поэтому
линейный прогноз подаётся как **консервативная нижняя оценка**, а рядом даётся
требуемый темп остатка — величина, не зависящая от гипотез о сезонности.

| Статус | Центров |
|---|---:|
| опережение | 9 |
| в графике | 2 |
| риск | 2 |
| срыв | 5 |
| без базы (центр запущен в отчётном году) | 2 |

Отдельный статус «без базы» введён намеренно: у Карандаша и Театриума значение
предыдущего года равно нулю, прирост «к предыдущему году» для них не определён,
и записывать их в срыв плана было бы ошибкой.

## 10. Интерфейс

Четыре раздела: обзор сети, аудиторные модели, рекомендации, качество данных.
Тема светлая и тёмная, переключатель перекрывает системную настройку в обе
стороны.

Отдельно про цвет на графиках. Пять кластеров нельзя показать пятью
категориальными цветами на одной диаграмме рассеяния: на ней в сравнении
участвуют **все** пары цветов, и ни один набор из пяти оттенков не проходит
контроль различимости одновременно в светлой и тёмной теме (перебор всех
сочетаний — 0 проходящих). Поэтому пространство кластеров показано **малыми
кратными**: пять панелей с одной и той же проекцией, в каждой выделен свой
кластер, остальная сеть дана приглушённым серым. Пять групп различаются
положением и подписью, а не оттенком.

Четыре цвета используются там, где сравниваются только соседние элементы
(составные столбики каналов аудитории) — этот набор проверку проходит в обеих
темах. Статусные цвета всегда идут со значком и подписью, чтобы значение
никогда не держалось на одном цвете. У каждого графика есть табличный
эквивалент.

## 11. Ограничения

Честный список того, чего эта работа не делает.

1. **Обратной связи нет в данных** — оценок мероприятий, отзывов и NPS платформа
   не показывает, потому что их неоткуда взять. Заменители (конверсия в продукты,
   доля резидентов) — это прокси, а не замена опроса аудитории.
2. **Динамики как временного ряда нет** — две точки на организацию. Всё, что
   касается «графиков динамики», реализовано как план-факт и прогноз года.
   Полноценные тренды появятся после второго отчётного периода.
3. **Двадцать наблюдений** — это мало. Отсюда и ограничение k ≤ 5, и правило
   парсимонии, и то, что каждый вывод сопровождается мерой доверия. Кластеры
   0 и 2 имеют невысокий силуэт (0,23 и 0,18) — их границы стоит считать
   ориентировочными.
4. **Эффект рекомендаций не проверен на практике** — он оценён как разрыв с
   эталоном сопоставимой группы. Это обоснованная оценка потенциала, а не
   предсказание результата: проверить его можно будет, сравнив прогноз со
   следующим отчётным периодом.
5. **Сезонность не моделируется** — линейная экстраполяция девяти месяцев на год
   занижает прогноз для центров с осенним пиком.
6. **Интерфейс не проверен визуально в этой сессии** — браузер был недоступен;
   контракты API и сборка проверены автоматически, вёрстку стоит открыть глазами.
